# 株価予測アプリ (stock-predictor)

会社名または銘柄コードで検索し、過去の株価チャートと将来予測(モンテカルロシミュレーション)を表示するWebアプリ。依存パッケージなしのNode.js単体で動作します。

## 起動

### Docker(推奨)

```bash
docker compose up -d
```

docker compose が無い環境では build + run で同じことができます。

```bash
docker build -t stock-predictor . && docker run -d --name stock-predictor -p 3900:3900 stock-predictor
```

いずれも http://localhost:3900 で開きます。ポートを変える場合は `-p 8080:3900`(compose なら `ports` を編集)。

株価スナップショットはイメージに同梱され、コンテナ内で自動更新されるためボリュームは不要です(コンテナを作り直すと同梱時点に戻り、起動後に再取得されます)。更新結果をホスト側に残したい場合だけ `docker-compose.yml` のボリューム設定を有効にしてください。

### Node.js を直接使う場合

```bash
node server.mjs
# → http://localhost:3900
```

## 機能

- **銘柄検索**: 日本の全上場企業(JPXリスト約3,700社)+ 主要グローバル株のローカル辞書で検索。会社名の一部(「トヨタ」)でも銘柄コード(`7203.T`、`AAPL`)でも引ける。ローカル辞書にヒットしない場合のみ Yahoo Finance の検索APIにフォールバック。
- **株価履歴**: サーバー側プロキシ経由で取得し、15分間メモリにキャッシュ。期間は1年/2年/5年。
- **予測**: 直近約250営業日の対数リターンからドリフトとボラティリティを推定し、幾何ブラウン運動(GBM)で3,000パスのモンテカルロシミュレーション。30/60/90営業日先の中央値と50%/90%信頼区間をファンチャートで表示。
- **指標**: 現在値、予測中央値、年率ボラティリティ、年率トレンド、上昇確率、SMA25/75。
- **予算スクリーニング**(「予算で探す」タブ): 予算額を入れると、その金額で1単元(100株)買える銘柄を一覧表示。市場・業種で絞り込み、1単元金額の高い順/安い順に並べ替えできる。行をクリックするとその銘柄の予測を開く。**日本株のみが対象**(単元株の概念があるため)。

## 予算スクリーニングの仕組みと更新頻度

全銘柄の株価を都度取得するのは現実的でないため、日本株約3,700銘柄の終値を `prices.json` にスナップショットとして保存し、そこから絞り込む。FTは1リクエストで50銘柄まとめて返せるので、全銘柄の更新は約75リクエスト・1〜2分で終わる。

更新対象は性質の違う2つに分かれる。

| データ | 中身 | 変化の頻度 | 更新方法 |
|---|---|---|---|
| `prices.json` | 各銘柄の終値 | **毎営業日** | サーバーが自動更新(既定24時間ごと)。`REFRESH_HOURS` で変更、`0` で無効 |
| `symbols.json` / `ft-xids.json` | 銘柄一覧・銘柄名・市場・業種 | 新規上場や市場変更があったときだけ | 手動。月1回〜四半期に1回で十分(下記「symbols.json の更新」) |

株価が古いと「予算10万円で買える」の判定が境界付近でずれる(例: 990円の銘柄が1,100円に上がっていても一覧に残る)ため、`prices.json` は毎営業日の更新を推奨する。スナップショットの株価日付は画面にも表示される。

手動で更新する場合:

```bash
node build-prices.mjs --full    # 全銘柄の終値を取り直す
node build-prices.mjs           # 未取得の銘柄だけ取得(初回構築の再開用)
```

## データソース

株価データは2系統から取得し、1つ目が失敗したら自動的に2つ目に切り替わる。

1. **Yahoo Finance** (`query1` / `query2` の chart API) — セッションcookieを取得した上でアクセスし、2ホストを順に試す
2. **FT (markets.ft.com)** — Yahoo が 429(レート制限)などで失敗したときのフォールバック。銘柄コードから FT の `xid` を検索し、取得した時系列を Yahoo 互換の形へ変換してフロントに返すため、フロント側はデータ元を意識しない

どちらも認証キー不要の公開エンドポイントなので、APIキーの設定は必要ない。両方失敗した場合は、期限切れのキャッシュが残っていればそれを返し、無ければ画面に再試行ボタン付きのエラーを表示する。

Yahoo は同一IPからのアクセスが続くと数十分〜数時間レート制限がかかることがある。その間も FT 経由で通常どおり動作する。

## 環境変数

| 変数 | 既定値 | 説明 |
|---|---|---|
| `PORT` | `3900` | 待ち受けポート |
| `REFRESH_HOURS` | `24` | 予算スクリーニング用の株価スナップショットを更新する間隔(時間)。`0` で自動更新を止める |

## APIエンドポイント

| パス | 内容 |
|---|---|
| `GET /api/search?q=<文字列>` | 銘柄検索。`{ quotes: [{ symbol, shortname, exchDisp }] }` を返す |
| `GET /api/chart?symbol=<銘柄>&range=<1y\|2y\|5y>` | 株価履歴。Yahoo chart API 互換の形式 |
| `GET /api/screen?budget=<円>&market=&industry=&sort=<desc\|asc>&limit=` | 予算内で1単元買える銘柄。該当件数と一覧を返す |
| `GET /api/screen-meta` | スナップショットの概要(収録銘柄数・株価日付・業種一覧) |

## ファイル構成

- `server.mjs` — 静的配信 + 株価APIプロキシ(cookie取得・15分キャッシュ・Yahoo障害時はFTにフォールバック)+ 予算スクリーニングAPI。依存パッケージなし
- `public/index.html` — UI一式(検索、Canvasチャート、予算スクリーニング。予測ロジックはクライアント側)
- `prices-source.mjs` — 株価スナップショットの取得処理(FTから50銘柄ずつ一括取得)
- `build-prices.mjs` — スナップショットを手動で作り直すコマンド
- `symbols.json` — 銘柄辞書。JPX公式の上場企業一覧(data_j.xls)から生成
- `prices.json` — 日本株の終値スナップショット(予算スクリーニング用、自動更新)
- `ft-xids.json` — 銘柄コード → FT内部IDの対応表。一度作れば変わらない
- `Dockerfile` / `docker-compose.yml` — コンテナ定義。node:24-alpine・非rootユーザー(node)で実行、約230MB

## symbols.json の更新

JPXの[東証上場銘柄一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)から `data_j.xls` をダウンロードし、内国株式のみ抽出して `{s: "コード.T", n: "銘柄名", x: "市場", i: "業種"}` の配列に変換する。新規上場・上場廃止・市場区分変更を反映するためのもので、月1回〜四半期に1回で十分。

更新後に `node build-prices.mjs` を実行すると、増えた銘柄のxidと株価だけが追加取得される(既存分は再取得しない)。

## 注意

予測は過去の値動きの統計のみに基づく参考値です。決算、ニュース、金利や為替などの市場環境といった要因は一切考慮していません。投資助言ではなく、教育・参考目的のツールです。投資判断はご自身の責任で行ってください。

株価データは外部の公開エンドポイントに依存しているため、提供側の仕様変更や制限により取得できなくなる可能性があります。
